# 文章写作与排版规范

本文以 `MPC_formula_derivation.md` 和 `MPC_from_cost_to_engineering.md` 为主要参考，统一博客文章的结构和排版。规范约束表达方式，不要求不同主题使用完全相同的内容模板。

## 标题与 front matter

- 页面标题只写在 front matter 中，正文不重复一级标题。
- 标题采用 `[领域] 具体主题` 的形式，例如 `[MPC] 从代价函数到滚动优化与工程落地`。
- 中英文、数字与中文正文之间保留必要空格；技术名称使用社区通行大小写，例如 `C++`、`ROS2`、`MPC`。
- 每篇文章保留 `title`、`date`、`draft`、`article_status`、`applicable_versions`、`comments` 和 `tags`。

## 文章结构

- 使用 `## 写在前面` 交代问题、范围和读者将得到什么。
- 使用 `##` 组织文章主线，使用 `###` 表达子主题；`####` 仅用于步骤或更细的推导层级。
- 标题应直接说明内容，避免“更进一步”“再进一步”“其他”等缺少语义的名称。
- 长文宜在结尾使用 `## 总结`、`## 结论` 或等价的主题化收束章节。
- 流程型文章可保留编号，但编号应位于同一父章节下，避免把每一步都提升为主章节。

## 正文表达

- 段落围绕一个中心意思展开，避免连续使用分号拼接多个独立判断。
- 首次出现的缩写应给出中文含义或英文全称，后文保持同一写法。
- 关键结论、适用范围和容易混淆的概念使用引用块 `>` 提示。
- 命令、类型、函数和字段使用行内代码，例如 `dds_write()`、`std::unique_ptr`。
- 列举并列概念时使用列表，不用连续短句模拟列表。

## 公式与代码

- 行间公式使用独立的 `$$` 块，起止分隔符各占一行。
- 一个公式块只表达一个连续推导；公式前说明目的，公式后解释符号或结论。
- 不在公式中保留可能被 Markdown 识别为标题或 HTML 的裸行，例如单独一行的 `=` 或裸 `<`。
- 多行等式使用 `aligned`，矩阵按行换行；公式编号 `\tag{}` 放在允许的位置。
- 代码块必须标注语言；代码中的注释保留在代码块内，不能误写成 Markdown 标题。

## 发布前检查

1. 正文是否没有重复 H1。
2. 标题层级是否连续且语义明确。
3. 公式是否全部由 MathJax 接管，没有残留分隔符或红色错误。
4. 中英文术语、标点和空格是否保持一致。
5. Hugo 生产构建是否成功。
